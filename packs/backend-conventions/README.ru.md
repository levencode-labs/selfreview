# Backend Conventions

[English](README.md)

Пакет для ревью C# и SQL по Git-диффу. Он содержит автоматические сигналы для C#, MVC, тестов и SQL, а также ручной чек-лист. Каталог правил и чек-лист хранятся вместе. [Каталог](catalog.json)

[Примеры ручной проверки с ожидаемым результатом](../../examples/conventions/review-scenarios.json)

## Установка

Из корня SelfReview перейди в `packs/backend-conventions`. Нужны Git, .NET 10 SDK и Node.js для прогона матрицы. Roslyn берётся из SDK.

```text
dotnet build
node checks/run.mjs
dotnet bin/Debug/net10.0/BackendConventions.dll rules
```

Чтобы установить навык для Codex или OpenCode, скопируй его в каталог `backend-conventions` внутри пользовательских навыков. Укажи абсолютный путь к пакету в `BACKEND_CONVENTIONS_ROOT`. [Навык](skills/backend-conventions/SKILL.md)

## Проверка

Возьми точные base и head из MR или Git. Скопируй пример профиля в локальную игнорируемую папку. Задай пути каталогов относительно корня целевого репозитория:

- `include` ограничивает анализ этими каталогами.
- `test` содержит подтверждённые тестовые каталоги и каталоги тестовых объектов. В них проверяются ожидания и аннотации NUnit.
- `uiTest` опционально сужает сигналы Playwright до подтверждённых UI-тестов и POM внутри `test`. Распознаётся явный селектор XPath. Неявный XPath и фиксированные ожидания требуют видимого типа объекта Playwright.
- `sqlUtf8` содержит каталоги SQL, для которых редакторская конфигурация требует UTF-8 без BOM. Остальные SQL-скрипты оцениваются вручную.

[Пример профиля](profile.example.json)

```text
dotnet bin/Debug/net10.0/BackendConventions.dll check <repo> <base> <head> <profile.json>
```

В JSON есть точные ревизии, счётчики файлов, находки, диагностики и чек-лист. Код 0 означает отсутствие автоматических сигналов в просмотренной области. Код 1 означает находки для ревью. Код 2 означает неполный анализ. Для каждого сигнала проверь контракт и исключения проекта.

C# разбирается в пределах одного файла со стандартными ссылками .NET. Внешние проектные сборки, global usings из соседних файлов, сгенерированный код и неактивные ветки препроцессора проверяются при ревью средствами проекта. Сигналы по явно указанным аннотациям NUnit могут опираться на синтаксис. Проверка SQL сравнивает появление BOM. Доменная семантика, транзакции и миграции проходят ручную проверку.
