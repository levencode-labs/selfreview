# Backend Conventions

Примени установленный **ponytail**. Подтверди Git-корень, точные base и head, постановку задачи и владельца области по метаданным проекта. Прочитай применимые инструкции репозитория, стандарт ревью, настройки .editorconfig и ReSharper. При работе с тестами открой соответствующие документы проекта и README тестового проекта.

1. Проследи изменённый сценарий от API или фоновой точки входа до наблюдаемого результата. Найди писателей состояния, существующие механизмы и сценарии отказа, повтора и смешанных версий. При реализации меняй только подтверждённую область.
2. Найди сборку в переменной BACKEND_CONVENTIONS_ROOT. Из клона каталог пакета находится на два уровня выше каталога навыка. Возьми локальный профиль с подтверждёнными каталогами. Запусти dotnet <pack>/bin/Debug/net10.0/BackendConventions.dll check <repo> <base> <head> <profile.json>. Команда анализирует зафиксированный дифф и связанные диагностические строки через Git и Roslyn.
3. Сверь находки с действующим правилом и исключениями. Для контекстных решений пройди применимые пункты manualChecklist из результата. Прочитай связанные файлы из того же снимка. При диагностике или отсутствующем снимке укажи пробел проверки.
4. Для подтверждённой проблемы укажи путь и строку, сценарий, последствие, правило и минимальное исправление. Сообщи ревизии и результаты. Продуктовые тесты выбирай по правилам проекта и его требованиям к запуску.

При обновлении набора проверяй историческое замечание по действующему источнику и ответам. Сохраняй исходные обсуждения и привязки проекта в локальном хранилище. Положительные формы и контрпримеры записывай вымышленным кодом.
