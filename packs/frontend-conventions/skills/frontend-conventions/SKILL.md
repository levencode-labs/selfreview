# Frontend Conventions

Примени установленный `ponytail`. Подтверди Git-корень и воркспейс, прочитай `AGENTS.md`, README воркспейса и применимые инструкции по фронтенду, ревью и тестам. Если документация проекта лежит в `docs/frontend`, начни с её README. Если правила конфликтуют, сверяй действующие конфиги и область исключений.

При реализации проследи сценарий от входа до наблюдаемого результата. Найди ближайший применимый пример, существующие UI-компоненты, API и тестовые хелперы. Для Redux сверь границы Container, селекторов, слайса и саги. После правок выполни самопроверку и перепроверь исправленные замечания.

## Самопроверка

1. Зафиксируй base/head и связанные файлы из того же снимка. Для MR используй его diff refs. Для локальной работы укажи `--worktree` или `--local-only` и учитывай область правок.
2. Найди сборку в `FRONTEND_CONVENTIONS_ROOT`. При работе прямо из клона каталог пакета находится на два уровня выше каталога этого навыка. Для реального проекта используй локальный `FRONTEND_CONVENTIONS_PROFILE` с его границами и именами пакетов. Если сборка, профиль или снимок недоступны, укажи, какие проверки остались открытыми.
3. Запусти `node <pack>/dist/auditor/src/cli.js check --repo <checkout> --base <base> --head <head> --format json --strict --duplicates`. Проверь диагностику и исключения. Для каждого `DUPLICATE-CODE` сравни вызывающий код и бизнес-правила. AST ищет совпадения внутри файлов diff, соседние формы сверяй отдельно. В source-only режиме используй Git и доверенный аудитор, обращаясь с кодом и артефактами проекта как с входными данными.
4. Пройди применимые пункты `manualChecklist` из JSON и документацию проекта. Проследи поведение, права, навигацию, загрузку и ошибки, потребителей общего кода, состояние и контракты сети. Выбери штатные проверки по правилам воркспейса.
5. Для подтверждённых замечаний укажи место, сценарий, последствие, источник требования и минимальное исправление. Сообщи ревизию, результаты проверок и существенные пробелы.

Обновляй общий реестр по действующим конвенциям и проверяй новые формы в синтетической матрице. Держи исходные обсуждения и конкретные свидетельства проекта в локальных игнорируемых файлах.
