# Frontend Conventions

[English](README.md)

Переносимый набор проверок JS, TS и React. В нём общий реестр детекторов, CLI для Git diff, адаптер ESLint, ручной чек-лист и воспроизводимая синтетическая матрица. Выбери целевой проект явно. Применимость и исключения сверяй с его документацией и штатными проверками.

[Примеры ручной проверки с ожидаемым результатом](../../examples/conventions/review-scenarios.json)

## Восстановление из клона

Из корня SelfReview, с Node.js 22.13+ и Git, выполни:

```text
cd packs/frontend-conventions
npm ci --ignore-scripts --registry https://registry.npmjs.org
npm test
node dist/auditor/src/cli.js rules
```

Скопируй [файл навыка](skills/frontend-conventions/SKILL.md) в `frontend-conventions/SKILL.md` внутри пользовательского каталога навыков Codex и OpenCode. Укажи абсолютный путь к этому пакету в `FRONTEND_CONVENTIONS_ROOT`, чтобы установленный навык нашёл сборку в клоне.

Для реального проекта скопируй [пример профиля](profile.example.json) в игнорируемый каталог, например в `.selfreview/frontend-conventions/profile.json` относительно корня SelfReview. Подставь значения из нужного checkout и укажи абсолютный путь к файлу в `FRONTEND_CONVENTIONS_PROFILE`.

| Поле | Откуда взять значение |
| --- | --- |
| `targetApp` | Путь от корня Git до исходников воркспейса, где действуют локальные правила по хукам и раскладке. |
| `appUi`, `legacyUi` | Имена актуального и прежнего UI-пакетов приложения из manifest или импортов. |
| `reactUi`, `icons`, `typography` | Имена пакетов компонентов, иконок и типографики из импортов проекта. |
| `dateImplementation` | Путь от корня Git к реализации утверждённой обёртки для дат. |
| `sharedUiDirectory` | Имя папки общего UI, где действуют исключения для SVG и локального состояния. |
| `configFile`, `disableDirective` | Имя существующего конфига аудита и маркер точечного отключения, если они уже используются проектом. |

CLI и ESLint используют один и тот же профиль. По умолчанию подставляются вымышленные имена для прогона матрицы. Для реального ревью передай checkout и обе ревизии явно.

```text
node dist/auditor/src/cli.js check --repo <project> --base <base> --head <head> --format json --strict
```

Код 0 означает отсутствие блокирующих находок. Код 1 означает BLOCK или MUST в строгом режиме. Код 2 означает неполный анализ в строгом режиме. Сверь диагностику, точный Git-снимок и пройди применимые ручные пункты. [Реестр и чек-лист](core/src/registry.ts)

## Матрица

Каждая строка [синтетической матрицы](checks/matrix.json) содержит правило, вымышленный пример, ожидаемый результат и нужный контекст пути или диффа. `npm test` проверяет покрытие каждого активного правила, сравнивает совпадающие поверхности CLI и ESLint и проверяет Git-снимок и профиль во временном вымышленном репозитории. Два случая фиксируют границы ручной проверки. Код примеров только разбирается парсером.

Храни профиль реального проекта, исходные обсуждения, свидетельства и результаты ревью в локальных игнорируемых каталогах.
